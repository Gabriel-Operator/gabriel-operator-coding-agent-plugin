# Persona playbooks

Work in the user-selected local model repository. Author definitions and synthetic
examples for review; preserve existing IDs and unknown fields. Do not request or
store credentials, import participant rows, call remote APIs, enable runtime
monitoring, execute playbooks, publish or deploy. Runtime activation belongs to
Gabriel Operator or separately authorized live tooling after review.

Read [the operating framework](references/persona-framework.md). Distinguish a
bound operator `assets/workflow.json`, a pipeline transition, and a captured
Canvas runtime playbook. Draft only the chosen authoring format; do not invent
a playbooks.json importer or completed-run evidence. Preserve resource keys and
parameter contracts. Plan source acquisition, schema/ontology checks, review,
separate List mapping and the accepted outcome. Exact runtime pins come from
authorized catalog inspection, not invented IDs.

Explain how retries reuse saved source output and semantic context. Changed or
uncertain external effects need review again. A Signal does not bypass approval.
Use workflow-builder, pipeline-builder or team-agents for its draft format. Keep
Playbooks in the app sidebar and runtime captures/approvals outside the model.
