# Persona team manager

Use the common Studio authoring service. Do not push directly to a persona repository or edit database projections. Read [the contract](references/contract.md), [the definition schema](references/studio-teams.schema.json), and [Lane's model](references/lane-meeting-cycle.md). The bundled validator and API helper work without a platform source checkout.

## Discover and author

1. Use the signed-in member's persona/workspace-scoped credential. Keep it in `GABRIEL_API_TOKEN`; set `GABRIEL_BASE_URL` to their HTTPS origin. Never put credentials, account selections, enrollment or raw execution data in a definition. Revoke short-lived agent credentials after the session.
2. Export with `node scripts/team-manager.cjs export snapshot.json`. This returns the existing asset, workspace revision and Git head. A missing repository requires explicit workspace setup; opening Studio must not provision Git.
3. Preserve all unrelated definitions. A team references registered workspace playbooks by `studio:<key>` and their exact source fingerprint. Calculate a registered workspace book’s normalized fingerprint with `node scripts/team-manager.cjs fingerprint playbook.json`. Existing persona bots retain their current registered reference. Use a registration destination explicitly: workspace library by default, then optionally reference it as a team bot. Persona-template publication requires the existing author authority.
4. Offer **Build from steps** (`kind: structured`) and **Plan from a goal** (`kind: goal`). Honor an already specified choice. Registration saves a definition and never starts execution. Goal playbooks need an objective, completion criteria, named inputs, connector requirements, allowed skills and root limits; no authored steps or prior run is necessary.
5. Save a proposal containing `asset`, `expectedRevision` and `expectedHead`. Validate offline: `node scripts/team-manager.cjs validate proposal.json`. Preview against current authority: `node scripts/team-manager.cjs preview proposal.json`. Commit only the reviewed proposal with `node scripts/team-manager.cjs commit proposal.json`. A conflict requires export, merge and another preview; never replace concurrent edits blindly.
6. Existing teams can be explicitly migrated with `node scripts/team-manager.cjs call migrate_definitions empty.json`. Migration preserves identities and runtime links; it neither runs bots nor grants connections.

## Run and inspect

Use `app_studio_start_playbook` only when execution was requested. Supply a stable idempotency key, explicit model-call and credit ceilings, fresh inputs and allowed shared fields. Read `app_studio_get_playbook_run` for the observable task tree. Descendants retain the initiating member and root limits; temporary specialists never become permanent team members. Completion requires inspected evidence and independent verification, not a model's completion claim.

Use personal connector requirements for mailbox/calendar/source operations. Use an app destination requirement for the separately configured shared publisher. A connector is an operation contract; a connection is a private authenticated account; the vault protects its credentials; an app renders shared results. Installing an interface does not grant a playbook access to its account. For its self-contained schema, UI starter and controls, call app_studio_app_builder_skill and download the returned authenticatedPackUrl with this team key. The Team Manager ZIP also includes the connector-app-builder pack. Use connector-app-builder for an app with its own custom UI and explicit connector prerequisites. Apps → New app opens that authoring guide; Connectors → My connectors is a direct MCP/REST connection form. Team-scoped agents can preview and register private UI packages using app_studio_preview_private_app and app_studio_register_private_app, then app_studio_install_connector with the primary connectionId and named connections. Use app_studio_app_data to inspect it and app_studio_configure_app to prepare bindings, change connections, adopt a revision or remove that installation. The setup key cannot enable synchronization or automatic rules. This retains the member’s identity, cannot publish a persona, and starts no automation. app_studio_prepare_rest_connector saves declared REST operations; the user adds any credentials in My connectors.

Use `connection_setup` before starting to inspect the selected playbooks’ requirements and your account readiness without creating a run. Canvas → playbook list → Create or edit exposes these mappings. An unavailable connection creates a durable setup request. Only its targeted member may finish setup, with real authentication, selected resources and operation mappings. A message saying “connected” is not proof. Call `app_studio_resolve_connection_request` after setup; resume the same execution, preserving previous effect receipts. Do not borrow the owner's personal accounts. Review external effects with their exact operation fingerprint; do not retry uncertain writes with a new identity.

Use [result mappings](references/result-mappings.md) for nested provider results and arrays. Preview the exact projection against sanitized fixtures with `preview_result_mapping`, then bind it as `resultMapping`. Plain JSON Pointer `resultFields` mappings remain supported. Never invent provider semantics or claim a fixture preview certifies a live account.

## Learning and recovery

Capture only a fully accepted goal run. The candidate retains authored goal instructions and safe named-input mappings, excluding result payloads, credentials, private runtime prose and account identifiers. Reasoning remains a goal-planning segment. The owner reviews the candidate before adoption; later runs use fresh inputs, grants, evidence and effect approvals. Preserve earlier procedure revisions.

If Git committed but projection failed, export and compare the accepted asset before retrying activation. Do not provision a new repository or invent replacement IDs to hide interrupted publication. Report unresolved recovery explicitly.

## Team Quick Start and scoped sessions

For a team created from Studio, connect with OAuth sign-in or a Quick Start key using its exact `GABRIEL_TEAM_MCP_URL` (`/api/studio-team-mcp/<persona>/<team>/workspaces/<workspace>`). Both methods expire after one hour and cannot authenticate to general Gabriel APIs. OAuth uses the team URL as its exact resource audience, offers only `studio-team:author`, rechecks current write access on every use, and cannot be extended by refreshing. The connected assistant should first call `app_studio_team_manager_skill` for this guide and its references; installing the skill is optional. The authenticated `/team-manager.zip` endpoint distributes a self-contained pack (including connector-app-builder). It retains the member's identity. Definition commits use the workspace owner's Git credential only after validating that other teams, their transitive dependencies and spending limits are unchanged. Never ask for or reuse the author's token.

Interview the user about outcomes, completion checks, timing, existing playbooks, steps versus goals, private sources, shared destinations, Lists, pipelines, apps, resource/field mappings and approvals. Ask only unresolved questions. Present the proposed canvas before previewing and committing. Team-owned library playbooks carry `teamId`; add their exact normalized fingerprints to the team's bot references. Registration starts no execution. New teams start empty in Quick Start. Playbook browsing, drag-and-drop, editing and removal live inside the Canvas library panel. The help button reopens Quick Start.

Discover the scoped MCP tool list. It includes export, preview/commit, playbook registration/edit/removal, team page/note tools, private connector account discovery, MCP inspection, preparing an OAuth connection, installation and logical operation mapping. Complete account sign-in in Gabriel. `app_studio_finish_team_setup` finishes the reviewed setup after at least one playbook was added. Owner-only activation, private accounts belonging to another person and effect approvals cannot be delegated through this key.

When using the bundled helper, set `GABRIEL_TEAM_MCP_URL` and `GABRIEL_API_TOKEN`. `export`, `preview`, `commit` and `call` then use that scoped MCP endpoint. Ordinary workspace credentials still use the documented REST transport. Revoke setup keys or end OAuth sign-in sessions in Persona app → Audit logs → App access after use. Never extract an OAuth token from the assistant’s saved configuration to feed a helper; use its native MCP tools, or ask the user to supply a separate setup key through the helper environment.

## Execution and verification

Studio uses Gabriel’s integrated Work board and coordinator by default. Mastra is the execution foundation, not another user-selectable service host. Keep external Factory/hosted routing only when explicitly configured. The goal and team configuration wizards separate the outcome and members, harness/model, and final review with connector setup and limits.

Declare every required MCP capability in the registered playbook's `requirements`. Include the requirements of reusable child playbooks. Canvas integration badges and task cards derive from those definitions; do not attach guessed providers to unrelated List-only playbooks. `GET /spaces/:teamId/connector-readiness` returns the current member's setup status with safe metadata. Admission rechecks it server-side for the selected bots. A ready account alone is insufficient: map the permitted operation, selected resources and result projection. Recurring setup/revocation still uses durable targeted conversation waits. A connector badge names provider capability; an App remains an interface over team data.

Task progress shows authored step metadata and the actual selected connector. It never copies private source results, credentials or account IDs into the board. For a small read-only acceptance run, import `assets/lane-calendar-check.json` into a new empty Lane team, bind personal Google Calendar's `list_calendars` read operation, and map its result to `{ "readSucceeded": true }` only after verifying the live tool succeeds. Share only `readSucceeded`. Registration starts no work and does not enable recurring automation.

Native programs support registered playbook reuse, bounded goal delegation, connector operations, shared List/page publishing, durable provider waits and coordinator dispatch. Typed workflow and pipeline operations reference pinned registered single-operation playbooks. Workspace-owned definitions never include account selections or raw traces.

For private handoffs in one coordinated goal, use an accepted assignment's `programRunId` and `programOutputFields`. Pass the input string `studio-output:<runId>#/<outputField>` to another Studio bot; `studio-output:<runId>#` selects only all declared outputs. The runtime resolves the declared output privately for the same initiating member, workspace, team and parent goal. Do not paste private replies or transcripts into shared task inputs. Transitive source grants are retained and checked before later work and publication; revocation creates a targeted setup wait. Use shared status projections to decide which bot runs next, without exposing private payloads to the board.

Lane's model uses private Calendar/Gmail, bounded Inkbox briefing calls and a consented capture adapter, then one shared Notion publisher and authorized List/page outputs. Read [production setup](references/production-setup.md) before connecting accounts. Recall's official MCP currently exposes investigation and webhook-management tools; do not claim it can create meeting bots. For meeting capture, prefer the native Recall adapter using the initiating member’s active AI Resources connection: inspect `capture_connections`, then `bind_capture_connection`. It supplies only consented scheduling and authenticated completed-transcript retrieval. A supported remote MCP gateway or verified transcript source remains an alternative. Browser automation is outside this release.

Native capture supports two distinct operation pairs: `schedule` / `transcript` for an enrolled meeting cycle, and `schedule-consented` / `completed-transcript` for a standalone playbook. Pass the exact pair when binding. Standalone capture requires a member's exact effect review with `captureConsent: true`, covering the booked link, start/end times, participants and current account grant. An agent-provided `consent: true` input is insufficient. Repeated requests for the same occurrence are held instead of scheduling another bot. Registration or binding never grants recording consent or starts attendance.

Report schema checks, fixture acceptance, transport verification and live provider results separately. Fixtures are not certification. No live meeting cycle is enabled by importing the model.

## Team resources and model import

`resources`, `save_resource` and `resource_data` inspect, preview/save and read Git-managed team Lists, pipelines and app views. Resource definitions are versioned under the optional `resources` array in `assets/studio-teams.json`. Use expectedVersion, workspace revision and head. Inherited resources cannot be overwritten; archive team-owned definitions to retain their data. `import_team_model` previews a single-team model into a new empty team, adapting team IDs and exact playbook pins while preserving its existing budget. Registration starts no work. The owner separately reviews `publishers` / `configure_publisher` and connection grants in Gabriel.
