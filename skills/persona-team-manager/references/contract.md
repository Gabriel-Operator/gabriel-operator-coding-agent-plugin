# Portable team contract

`assets/studio-teams.json` has schemaVersion 1, optional saved ISO country `market`, teams and workspace playbooks. Git stores definitions. Runtime jobs, evidence, account bindings, approvals, enrollment and secrets remain in their scoped services.

Teams preserve IDs, names, goals, budgets, bot responsibilities, canvas positions and connections. Bot references carry registered template IDs and exact fingerprints. New bots are paused and gain no connections during activation. Existing runtime content is preserved. Use expected workspace revision and Git head for every commit. Full workspace authoring requires workspace-owner authority. Team Quick Start additionally supports the confined member-writing session described below; neither grants persona-template author authority.

Playbooks use a discriminated `kind`: `structured` contains ordered steps and dependencies; `goal` contains objective and criteria, contracts, requirements and delegation limits. Older definitions normalize to structured. Native goals default to depth 3 below root, 12 temporary agents, 32 tasks, 4 concurrent agents, 60 active minutes and 7 elapsed days. Stricter team limits apply. This release serializes dispatch within a root. Model-call and credit limits are explicit and shared across descendants.

Connector requirements name a logical capability, permitted providers and operations, and personal or app account context. `connector_operation` steps use safe JSON Pointer mappings; no arbitrary code or endpoint is evaluated. Effect reviews bind the current run, definition, node, operation and mapped inputs. The connector installation's pinned manifest enforces selected resources and discovered schema fingerprints. Shared output publishing permits only the intersection of the publisher's and initiating run's declared fields.

Agent REST transport: `POST /api/v1/app/studio/<operation>` with the existing persona/workspace-scoped token. MCP and coach use the equivalent `app_studio_<operation>` tool. UI routes under `/api/persona-playground/pages/<pageId>` call the same service. The helper accepts only explicitly listed operations and HTTPS origins; redirects are rejected.

## API operations

- `export_definitions`: current asset, revision and head.
- `commit_definitions`: full asset, expectedRevision, expectedHead, validateOnly.
- `migrate_definitions`: explicit migration of existing team identities.
- `register_playbook`: playbook, expectedVersion, expectedRevision, expectedHead, validateOnly.
- `start_playbook`: teamId, playbookKey, input, maxModelCalls, maxCredits, sharedFields, idempotencyKey.
- `get_playbook_run`: teamId, runId, optional kind (`program` by default, or `graph`). Private to the initiating member. A completed run with declared results includes `output.fields`.
- `app_studio_read_execution`: teamId and executionId. The Work view returns accepted playbook `outputs` alongside the execution and events.
- `cancel_playbook_run`: teamId, runId, cancelling pending descendants.
- `resolve_connection_request`: requestId, checked against the authenticated targeted member.

Runtime definitions are captured at creation. Revocation, current membership and account grants are checked again during dispatch. Never reuse an old approval or phone call. Uncertain writes use existing connector reconciliation instead of replay. Browser automation is outside the initial MCP execution contract.

## Decision execution

Set the playbook runtime target to `gabriel` and use `execution.profile: "decision"`. Define one `execution.question` with instructions. Use `type: "boolean"` for a yes/no decision, `type: "choice"` with an `options` array for a selected label, or `type: "score"` with a low-to-high `levels` array for a fractional zero-based score. Declare an `answer` output matching the question type. New typed answers are a boolean (true when the probability of yes is at least 0.5), selected label, or number. Definitions with the original answer object retain that record. A Decision playbook can be a goal or one analysis step. It evaluates the declared inputs in a fresh run without connector operations or delegated work.

Save the private account in profile settings → Models and accounts → Playbook provider connections. On the Canvas, open the playbook’s model section, choose Edit playbook model and connection, and verify the saved account under Your provider connections. For an existing Decision playbook, read `app_studio_playbook_runtime`, pass `target: "gabriel"` and the selected connection ID to `app_studio_provider_models`, and choose from the compatible models returned by the catalog. Use `app_studio_set_playbook_runtime` with that model and the current team and connection revisions. The OpenAI Decisions connection needs an OpenAI project key with Models read access and Decisions write access. TypeSafe uses its own API key. The runtime keeps the account selection private to the initiating member. Run history records the Decision provider and the model that responded.

Provider accounts belong to the signed-in user and can be reused across teams. Team settings manages team-scoped connections for services and goal execution. The person who added a playbook to the Canvas can change its private model account or provider connection. Editing the definition preserves that placement’s creator. Studio can recover the creator of an older placement from its recorded Canvas addition in Changes. If there is no creation record, the workspace owner manages the connection. Running a playbook follows the member’s assigned run permissions. Workspace owners manage shared channels, deployments and the team’s coordinator defaults.

## Playbook output and handoff contract

Read the same placed workflow that Studio uses through `app_studio_playbook_workflow`, with the team ID and the Canvas bot ID. Structured workflows require at least one executable step before they can be saved or run. Goal playbooks expose their input and output contracts and plan their actual steps during execution.

For a new single-result playbook, set `outputModality` and `outputFields: ["result"]`. For example, a `video` result is `{ "result": { "url": "https://example.com/clip.mp4", "mimeType": "video/mp4" } }`. Image and audio use the same keys with their respective MIME types. Text uses a string. Structured data can contain nested JSON. With a portable runtime, declare the value schema for `result` in `runtime.output`. Existing named fields and Decision answers remain valid. Map final fields to their accepted sources with `finalOutputMappings`, for example `{"result":"/steps/render/video"}`. With no mappings, the last authored step supplies the output.

Completed playbook outputs expose `modality` and a `result` value alongside the existing `{ name, format, value, source? }` list for field-level routing. A playbook with multiple declared fields wraps the released fields under `result`. Canvas shows the output modality. Select an output or a producing step in How it works to see its mappings in the right sidebar. The private run, shared Work execution, and Team SDK use the captured definition. The Team SDK keeps the goal summary in `data.result` and the playbook results under `data.outputs`. Sharing still requires a field release.

Declare an input’s `format` to display its modality. An existing structured output may use `outputDisplayFormat` to name the primary result format without changing its saved JSON fields. Select the output node for the `result` JSON schema. In the Skill Editor, `bot/workflow.json` Visual uses the same diagram as How it works. The code view links to the corresponding entry from `assets/studio-teams.json` or to the packaged journey source.

An authored human review may set `revisionTarget` to an earlier step, or `$inputs` for a workflow with declared inputs. Use `app_studio_get_playbook_run` for the current pending review fingerprint and `app_studio_request_program_changes` for the reviewer’s requested revisions. The changed work requires fresh approval. A completed external write or publication cannot be replayed through this path. Native completion records the evaluation after the result. Select `evaluationSubjectInputs` to identify the same subject across runs. Evidence-linked guidance is available to later runs for the same member, team, definition and subject, with current context access.

For cross-playbook inputs, the coordinator uses `accepted_results` followed by `assign_bot` with an optional `handoffs` map. Each target input names an accepted assignment and a JSON Pointer into its declared result, for example `{"research":{"assignmentId":"…","source":"/brief"}}`. The expression resolves inside the consuming run, preserves JSON types, and requires the producer to be accepted in that same goal. Independent tasks can run in whatever order the coordinator selects.

## Canvas authoring sessions

Team Quick Start uses `/api/studio-workspace-mcp/<pageId>` with `studio-workspace:author`. Browser consent lets the member select an editable persona workspace; `studioWorkspaceId` is stored on the authorization request and grant, and carried into the authenticated principal. Each dispatch resolves that same member and exact workspace again, independent of browser defaults. API session keys use an explicit workspace access marker and immutable workspace binding. Both methods default to one hour and let the member choose 1 hour, 6 hours, 1 day, 3 days, 7 days, 30 days, custom minutes/hours/days, or Until revoked. Finite deadlines do not slide on refresh; OAuth bearer tokens still expire within 24 hours and refresh tokens rotate. Until-revoked grants use an explicit persisted marker, not a missing deadline. Both methods remain subject to revocation and live membership, cannot use general Gateway/persona APIs, and preserve personal connection ownership. The consent screen uses the persona landing-header logo, never a profile portrait. End access in Persona app → Developer Console above Credits (Connected apps or Access keys), or the existing Audit logs access section. Call `app_studio_team_manager_skill`, download its authenticated `/team-manager.zip` pack, list teams with `app_studio_list_teams`, and pass `teamId` to team operations. `app_studio_create_team` creates an empty team that can be managed through the same connection. Export definitions, preview and commit each team's changes with its expected revisions and Git head; preserve unrelated definitions. Members cannot raise budgets or activate automatic work. Legacy `/api/studio-team-mcp/<pageId>/<teamId>/workspaces/<workspaceId>` URLs and `studio-team:author` keys remain confined to their original team and require a new workspace sign-in to gain broader access.

Workspace MCP also exposes `app_studio_update_team`, `app_studio_remove_team` and `app_studio_restore_team`: pass `teamId`, its current runtime `expectedRevision`, and `validateOnly` (true by default). Update accepts name/goal. Remove sets a versioned `archived` flag through the same Git preview/commit/activation service; it preserves definitions and runtime work. Enabled bots, background sources, active executions, enrollments, synchronization and monitoring must be stopped first. Archived teams cannot accept normal operations. List with `includeArchived: true`, then restore with its current revision; restoration does not start work or grant accounts. Other teams and legacy team-only credentials remain confined.

A team playbook may declare `teamId` to retain library ownership before being placed on a canvas. Removal from a canvas preserves the saved definition. Deleting a saved definition requires removing all references first; existing execution snapshots remain intact. Active assignments prevent bot removal.

The confined setup key can inspect `capture_connections`, but cannot call `bind_capture_connection`: attaching a meeting-capture account is completed by the signed-in member in Gabriel. It never grants recording consent. The full authenticated runtime tool and helper operation remain available to credentials with their existing run authority.

Native Inkbox briefings reuse a permitted AI Resources phone connection owned by the member. Other members need their own private connection. Calls require a verified profile destination, exact effect approval, a maximum 180 seconds, signed single-use media, known carrier pricing and at most $1 carrier cost. Uncertain dispatch stays held; the same request cannot dial twice.

Shared publishers are configured separately with `configure_publisher`, expectedRevision, kind (`page`/`list`), destination and field allow-list. Publication requires the member's output consent and every private source grant. Lists use validated values, stable insertion keys and revision-checked updates; shared receipts expose only published fields.

## Shared resource definitions

The optional `resources` array contains strict versioned `list`, `pipeline` and `app` definitions with a stable key and teamId. Lists define typed columns; pipelines reference a team List and declared stages/transitions; app views select an authorized List field projection and optional board pipeline. Connector transitions pin a compatible registered single-operation playbook. Use `resources`, `save_resource`, `resource_data` and `import_team_model`. Validate the whole graph before committing, then activate recoverable stable-ID projections. Runtime data is never put into the Git asset. Archive instead of dropping definitions. Existing inherited Lists retain their data-point permissions. Shared destination `publishers` are separately owner-approved runtime grants.

Native Recall accounts use verified durable status callbacks in production. A polling-only account is available for local Studio testing; it rejects every incoming callback, publishes no webhook URL and cannot join interactive Coach meetings. The API key is encrypted and stays outside Git; a callback secret is neither invented nor substituted with the API key. Existing signed-callback accounts keep their verification requirement.

Connector bindings support bounded declarative `resultMapping` projections for nested arrays and fields, retaining legacy `resultFields`. See [the mapping contract](result-mappings.md). `preview_result_mapping` validates sanitized fixtures without provider calls or persistent sample storage. Array, condition and work-limit failures stay visible; mappings cannot execute backend code.

`preview_connector_read` obtains a creator-private setup sample using an owned connection, exact discovered tool name, schema fingerprint, arguments and `confirmedRead: true`. The provider must explicitly declare the operation read-only, with no destructive hint. A setup key cannot use this operation for writes or unclassified actions. Treat samples as private runtime data; do not put them in Git or shared prompts. A successful sample does not install a connector, bind a requirement or approve an effect.

Standalone Recall bindings explicitly declare `operations: ["schedule-consented", "completed-transcript"]`; omitted operations retain the enrolled-cycle `schedule` / `transcript` contract. Review the exact pending effect and confirm every participant agreed with `approve_program_effect` using its nodeId, fingerprint and `captureConsent: true`. The grant is pinned to the member, account revision, operation and meeting details. Missing, changed, withdrawn or expired consent cannot schedule or retrieve a recording. Existing receipts reconcile after a timeout; a different run cannot create another bot for the same team/account/meeting occurrence.

Private inter-bot inputs use `studio-output:<runId>#/<declaredOutputField>` strings, optionally selecting a nested safe JSON Pointer. An empty pointer after `#` selects only the source book’s declared output fields. The referenced run must be completed and its assignment accepted inside the same parent goal, team, workspace and initiating member. Resolution occurs only inside the private destination run; shared assignments retain the reference, output field names and authorized status projection. Source identities and logical requirements propagate transitively and are rechecked before work, app writes and shared publication. No private output reference grants new tools or sharing fields.
