# Set up Lane in production

Use the deployed version containing Canvas library, Team Quick Start, scoped team MCP and Inkbox briefing support. Keep this distinct from a live-provider acceptance result: the local fixture cycle uses simulated providers.

1. Open Lane → Playbook Studio → New team. It opens empty in Quick Start. Existing teams keep their current canvas. The question-mark button opens Quick Start again.
2. Quick Start has three steps: **Create key → Connect assistant → Team prompt**. Create the one-hour setup key in step 1 to unlock the remaining steps. In Connect assistant, choose your coding agent and follow its MCP / OAuth instructions. For Claude Code, copy the HTTP add command, then run `claude mcp login my-persona-team` to open browser sign-in (or use `/mcp` → `my-persona-team` → Authenticate). Review this team’s one-hour access in the browser. A cloud assistant needs the production HTTPS URL, not localhost. Team skill is an optional connection guide: download and unzip its pack into your assistant’s skills folder, then connect using sign-in or the setup key. The connected assistant can load the guide itself with `app_studio_team_manager_skill`.
3. You can use **Import team model** in Quick Start to preview the bundled `assets/lane-studio-teams.json` and register its complete graph in a new empty team. This imports the Meeting cycles List, pipeline and app views alongside the playbooks, preserving the team’s budget and leaving automation off. Alternatively, copy the interview prompt from Quick Start. Explain the meeting preparation and follow-through workflow. The assistant exports current definitions and merges `assets/lane-studio-teams.json` without changing unrelated teams. It previews and commits the reviewed proposal, preserving existing IDs, revisions and head. Keep automatic work off during setup. Set a budget explicitly as the owner; the sample's team budget is zero.
4. In Lane → Connectors → Add connector, add **Google Calendar** and **Gmail** as your personal accounts. The managed path is **Use a managed connection → Load my managed accounts and operations → Connect another managed account**. Choose an existing Composio project key, or use **Add my Composio key** inside this form. New keys are encrypted in your private account store; connector accounts and operations remain separately selected. Complete Google sign-in yourself. Choose only the required calendar/email read operations. The alternative official remote MCP path uses its supported account authentication. Do not paste tokens into a conversation.
5. Add **Notion** separately. Give the integration access to the disposable Contacts database only. Select that database in the installation's immutable resource mappings. The owner maps it as the shared app destination; personal email/calendar access remains separate. Map exact attendee email → existing Notion page and current revision → existing Lane lead and current revision using `map_meeting_contact`. The database URL alone does not establish those row identities.
6. For the call, use **Inkbox**, with no Vapi account. In Lane’s AI Resources, connect the persona’s Inkbox identity, dedicated voice-capable number and webhook signing key, then enable it in **Phone calls**. Set destination pricing for the country prefix. The team respects the existing published phone capabilities and any stricter team resource policy. `briefing_phones` lists ready permitted identities; `bind_briefing_phone` maps one to the `briefing` requirement. Verify your own profile phone first. Other members must use their own private calling connection; they cannot borrow the owner’s persona identity.
7. In **AI Resources → Meeting note-taker**, attach your own Recall account. For production, enter the API key, correct region and separate workspace verification secret. Configure the displayed callback URL in Recall and subscribe to bot status, recording and transcript events. Verified callbacks are durably saved before acknowledgement, processed with retry and wake the waiting execution. Studio fetches completed transcript data after `transcript.done`; it does not poll production bot status. **Local testing only — use authenticated polling** is available for a local capture test without a callback secret and does not support incoming callbacks or interactive Coach meetings. Use `capture_connections` and `bind_capture_connection` to map it to the `capture` requirement. The native adapter uses the existing encrypted account for bounded bot scheduling and authenticated completed-transcript retrieval; no remote gateway is required for this path. Recall’s official MCP alone does not create meeting bots. A remote MCP adapter may be selected instead only when its discovered capabilities supply the required contract. Enroll specific meeting links only after participants consent. Capture must confirm the exact link, permitted recording, completed meeting time and nonempty transcript.
8. Open Canvas → playbook list → Create or edit → Playbook connections to configure accounts before execution; `connection_setup` returns the same requirements and readiness for coding agents. Map discovered operations and normalized result fields. The logical names `upcoming`, `search`, `call`, `status`, `schedule`, `transcript` and `update` are not assumed provider tool names. `assets/lane-meeting-resources.json` describes the normalized contracts and shared destinations. Test mappings against sanitized samples. An MCP with insufficient semantics stays unavailable.
9. The model import registers the team-owned Meeting cycles List, pipeline and two app views. Reuse Lane’s existing Leads/relationship Lists without replacing their definitions. Configure `meeting-cycles`, `leads`, `relationship-meetings`, `relationship-observations`, `relationship-outcomes` and `live-results` publisher grants with `configure_publisher`. Select an existing shared team page for the last destination. Inspect and review these grants under Canvas → playbook list → Create or edit → Shared output destinations. No page ID, credentials, phone number or real meeting URL belongs in Git.
10. Review the Canvas: watcher, goal researcher, caller, scribe, analyst and steward. The publisher is a reusable supporting playbook. The Canvas library supports Add, drag-and-drop, editing and removing a bot while retaining its definition. Review source-sharing fields explicitly; every private source grant must permit the fields that will enter Notion, Lists and shared pages.
11. The owner enables background work and activates the exact meeting policy. Each member separately joins recurring work with their own accounts, verified phone and consented meeting links. Registration and enrollment do not grant another person's accounts. Effect reviews remain separate. Missing account setup appears as a targeted conversation request; a text reply saying “connected” does not satisfy it.
12. Create a dedicated test Calendar event and relevant test email. Allow the five-minute watcher to discover it, with preparation 30 minutes before the meeting. Review the exact call and capture effects. Confirm one briefing call (maximum three minutes), consented capture, transcript completion, registered signal receipt, one Notion write, Lane lead status/notes and shared page/List updates. Revoke a source and verify the correct member is asked to reconnect without replaying a completed effect.
13. Capture the successful goal researcher’s procedure, have the owner review/adopt it, and repeat with a second test meeting and fresh inputs. Inspect private run receipts and the task tree from Canvas. Verify provider results and cleanup separately from fixtures.
14. Revoke the one-hour setup key or end the assistant sign-in session in **Audit logs → App access**. It expires automatically as well. Keep provider connections only as long as needed for ongoing work.

Reference provider contracts: [Inkbox calls](https://inkbox.ai/docs/api/phone/calls), [Recall MCP capabilities](https://docs.recall.ai/docs/mcp), [Recall bot creation](https://docs.recall.ai/reference/bot_create), [Recall bot retrieval](https://docs.recall.ai/reference/bot_retrieve). Signed provider callbacks must be verified by their existing connector ingress; signed connections use durable callback-driven completion and an authenticated final transcript fetch. Unsigned callback bodies are never accepted as evidence; polling mode is intended only for local testing.

For the separate **Prospect to pilot** journey, bind the native Recall account to `pilot-capture` with `operations: ["schedule-consented", "completed-transcript"]`. No recurring enrollment or remote capture gateway is needed for that adapter. When the scribe pauses, its private review shows the specific meeting link, interval and participants. The initiating member confirms every participant consented before approving. A value supplied by a bot is not recording consent. An expired meeting cannot create a new capture; a saved uncertain receipt is reconciled without a second creation. Use the existing callback setup above in production.

The coordinator passes accepted private replies, booked meetings and transcripts between these bots using scoped `studio-output:<runId>#/<field>` references. Shared Lists, pages and Notion receive only explicitly permitted projections. Review every source's field consent as well as the destination publisher grant; reconnecting one source must not replay a sent email or booked meeting.
