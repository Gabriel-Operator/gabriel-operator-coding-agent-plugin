# Package contract

An app directory contains `app-config.json`, `mcp-app.html` and bundled static assets (for bundle mode), and optional `fixtures/<entity-id>.json`. Use the included JSON schema. Maximum package: 4 MB, 100 files. File paths are relative, have no traversal, and use html/js/css/json/svg/txt extensions. Credentials belong to connection references and never the manifest or fixtures.

The manifest has `schemaVersion: 1`, `kind: studio-connector-app`, `name`, `description`, `source`, `view`, `entities`, `actions`, `ui` and `monitoring`. Optional `state: true` allows one JSON document. Optional `playbooks` declares the named runs the page may start. `source.endpoint` is remote HTTPS when the package uses a primary connector. Omit `source.endpoint` and `source.toolkit` when no operation, resource, or provider UI uses the primary source. Registration and installation then omit `connectionId`. Each entity has `id`, `label`, declared `fields`, `fieldsMap` (display field → remote item JSON Pointer), and a `read` operation; `write` is optional. An operation contains a discovered `tool`, its exact `schemaFingerprint`, fixed `arguments`, and extraction pointers `resultPath`, `idPath`, `revisionPath`. `cursorPath` and `cursorArgument` enable pagination. Result extraction uses structuredContent, or parsed JSON text when needed.

Only `$`-prefixed JSON Pointers in argument templates are dynamic. Examples: `$/values/title`, `$/remoteId`, `$/revision`, `$/cursor`, `$/idempotencyKey`. Everything else, including resource IDs, is pinned. Mappings do not evaluate JavaScript or JSONPath. Tools and schemas must match discovery at registration, installation and execution. Changed schemas hold work.

UI modes:

- `{kind: generated}` uses Studio's entity view.
- `{kind: bundle, entrypoint: mcp-app.html}` uses your compiled static UI. Include dependencies in the package. No CDN imports, arbitrary network fetch, parent cookies, provider tokens or general Gabriel API keys.
- `{kind: mcp-resource, resourceUri: ui://..., tool: discovered-tool}` selects a discovered provider HTML resource. Relative remote dependencies must already be self-contained. Requests still pass through the same installed resource grant.

The guest uses `App` from `@modelcontextprotocol/ext-apps`; compile it into the bundle. `app.ontoolinput` receives `{arguments: {items, manifest}}`. It does not receive saved state or the playbook allowance. For connector edits use `app.callServerTool({name: gabriel_connector_write, arguments: {entityId,remoteId,expectedRevision,values,requestId}})`. For connector reads use `gabriel_connector_read` with `entityId`; actions use `gabriel_connector_action` with `actionId,values,requestId`.

Declared host calls, rejected when the manifest does not declare that use:

- `gabriel_app_state_read` and `gabriel_app_state_write` when `state` is true. The document is one plain JSON object of at most 256 KB. A write sends `{ state, expectedRevision, requestId }` and returns `{ state, revision, updatedAt }`.
- `gabriel_app_list_read` with `entityId` for an entity bound to a List. Any direction may be read. The result includes mapped fields, the record id, and the mapped-field revision.
- `gabriel_app_list_write` for the same binding when direction is `outbound` or `both`. An inbound binding cannot be overwritten. Values contain only mapped fields. An update sends `expectedRevision`. A new row sends `requestId`.
- `gabriel_app_playbook_start` with `{ playbookKey, input, idempotencyKey }`. `input` keys must be listed in that playbook's `inputFields`. The manifest cap is the cost of one start. The owner sets the remaining allowance in the Apps tab. The page cannot raise it.
- `gabriel_app_playbook_status` with `{ runId }` for a run whose playbook key is declared on this app.

Supply a stable request UUID across retries. The host returns an MCP tool result. A provider UI can call its discovered native tool only when its complete arguments match an installed template; constants cannot be replaced. Unsupported tools/resources fail closed. The page keeps `connect-src 'none'` and never receives a token.

Bindings: `{entityId,source:list,resourceKey,direction:inbound|outbound|both,fields:{listColumn:appField}}`. `fields` maps a List column to an app field. The page reads and writes the List column names. Assets use `source:assets,direction:outbound`. New inbound List rows use a stable internal identity; existing rows use revision checks and List validation. Outbound data must have a committed team receipt. No remote deletion propagation. Inbound means the connector imports into the List, so the page may read that binding and must not write it.

Monitoring descriptors: `{id,label,entityId,detection:poll|webhook|none,event}`. Rules have a UUID `id`, positive `revision`, `event`, `entityId`, `conditions:[{path,operator:equals|contains|changed,value?}]`, `action:notify|draft|run`, optional `botId`, `prompt`, `taskFields:{taskField:JSONPointer}`, `inputs:{inputField:JSONPointer}`, `enabled`. Conditions and mappings use normalized entity data. Only taskFields and inputs leave the private source. Do not paste raw payloads into the prompt. Owner approval is server-managed and invalidates on rule/source/limits changes.

HTTP helper operations use `POST /api/gateway/connector-apps/<operation>`. Operations: connections, connect, inspect, list, preview, register, definition, install, configure, data, remove. Workspace operations include pageId, spaceId, personaWorkspaceId. Account REST inspection/package endpoints also exist under `/api/studio-apps/connectors`; Studio operations use `/api/persona-playground/pages/:pageId/spaces/:spaceId/connector-apps` with the active workspace selection.

Public registry membership is a capability ceiling. Account scopes, provider plans/previews, API approvals, operations and monitoring must still be discovered and configured. Read-only/process-only profiles cannot acquire unrestricted two-way synchronization by relabeling a custom operation.


## Separate interfaces and account connections

Bundled pages run in a scripts-only sandbox. Native form submission is blocked, including a form's submit event. Keep validation through the styled controls, use a button handler that checks the form's `reportValidity()` before calling the scoped bridge, and handle Enter on single-line fields explicitly. Do not add `allow-forms` or navigate the page to submit data. App playbook status includes its scoped `error`, `result` and `pendingEffects`; the host's **Review assistant action** link opens the exact private execution for effect review.

`source` describes the primary connector, authenticated with installation `connectionId`. Additional dependencies use `connectors: [{key:"crm",label:"Notion contacts",purpose:"Publish accepted follow-up",required:true,endpoint:"https://service.example/mcp"}]`. Put `connector:"crm"` on that dependency's entity read/write or action operation. `ui.connector` selects a dependency's provider UI; bundled UIs use entity/action IDs through the scoped bridge. `resources` remain on the primary connector. Dependency keys are unique; `default` is reserved. Operations cannot name undeclared connectors.

Preview and registration accept `connections:{crm:"user-connection-uuid"}` for checking available prerequisites. Installation requires all mandatory connections and validates every bound tool fingerprint and provider. No account IDs or secrets enter the portable manifest. The server rechecks ownership/revocation before every operation. Optional disconnected integrations cannot execute. Changing a binding requires edit access, current installation revision, disables synchronization in Studio, and invalidates automatic rules. Existing one-source packages need no changes.

For REST, connect with `{protocol:"rest",label,endpoint,operations:[{name:"list_contacts",method:"GET",path:"/contacts",readOnly:true}]}` through helper `connect` (or `gabriel_connect_connector_rest`). The base endpoint is HTTPS with no query or embedded secrets. `credential` is encrypted; omit `credentialHeader` for Bearer, or supply an authentication header such as `X-Api-Key`. Each fixed relative operation path can contain named `{id}` segments. Its normalized arguments are `{path:{id:"..."},query:{limit:10},body:{...}}`; GET and DELETE operations have no body. A documented read-only POST search may accept a body. Discover the exact schema/fingerprint before mapping it. Credentials never enter query/body mappings. No redirects, custom uploaded backend code, arbitrary URLs or MCP resource reads are available. The basic My connectors form saves one operation at the given endpoint; declare additional operations with the helper when needed. REST inspection validates configuration, not provider credentials; only an authorized read or actual operation verifies those.

With a team setup key, use `app_studio_app_data` and `app_studio_configure_app` for that team’s installations. Configuration requires `expectedRevision`; it accepts connection selections, an adopted `appRevision`, prepared `bindings`, and ready/paused/removed state. The key cannot set `syncEnabled:true`, prepare or activate automatic execution rules, or remove an account-level package used in another team.

### App appearance and launch

Set `manifest.icon` to your own SVG geometry: `{ "paths": ["M4 4h16v16H4z"], "viewBox": "0 0 24 24", "style": "outline" }`. Paths contain SVG path commands only (up to 16 paths); optional `color` is a hex color. Use `solid` for filled artwork. Markup, scripts, remote image URLs and emoji are not icon fields. The same icon appears on the app tile and title.

An opened app shows its interface immediately after required accounts are verified. The far-right Customize button reveals integration rows, launch options and collapsible advanced settings. Required accounts block both the UI and scoped operations until connected. Open app launches an app-only tab at `/studio-apps/<installationId>`. The owner chooses Owner only (default), Anyone signed in to Gabriel, or Public without login under Customize → App access → Sharing. The QR uses the current reachable HTTPS origin and the same access mode, with no credential in the URL. Every launch data/UI/resource/bridge request rechecks consent and the owner’s current workspace and connector grants. Shared consent pins the selected accounts, manifest, app revision and List mappings; changes require fresh owner approval. Shared visitors can read app data and invoke declared operations using the owner’s connections and remaining assistant allowance, while approval-required effects still need owner review. Shared access does not expose account management, package APIs, Studio, write receipts or automatic rules. Visitor state and assistant-run status are isolated. The owner can revoke sharing immediately by selecting Owner only. The standalone watermark reads `Made using [Gabriel](https://gabrieloperator.com/) Operator with <personaName>`. It follows the app content at page end and scrolls with the page. Leave the guest SDK’s default autoResize enabled so the host can size the frame to its content.

The bundled controls default to a light theme and share `--color-background`, `--color-foreground`, `--color-input` and related palette variables across inputs, date/time fields, textareas and select triggers/popovers. Set the app palette on `:root`; add `.dark` to the root only when the entire interface deliberately supports that theme. OS dark preference does not independently recolor fields inside a light app.
